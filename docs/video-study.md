# Reference study — Yoyo2

対象: ユーザー提供 MP4（247.17 秒）。映像フレームを抽出して観察。音声の解析は未実施。

## 観察した構成

- 冒頭は淡い灰色の面と黒い物体。約10–21秒では人物がほぼ黒いシルエットになり、背景の明暗が輪郭を決める。
- 約31–62秒では横長の白い帯、黒い余白、文字とその上下反転像が支配的。色数よりも輝度差と配置で空間を作る。
- 約72秒では文字列と光の帯が奥へ収束する。カメラ位置と遠近で、同じ要素が異なる空間に見える。
- 約82–113秒では人物と上下反転像の間隔・大きさが変わり、光の面と反射面の境界が画面を二分する。
- 約124秒の暗転に近い場面を挟み、約134–144秒では文字と明るい面を近距離から捉える。ぼけと斜めの境界が見える。
- 約154秒の円、165–175秒の矩形は、暗い空間に明るい図形が浮く構成。周囲に緩い光の広がりがある。
- 約196–216秒では反復する菱形状の白黒パターンと中心の人物、反射像で画面を構成する。
- 約227–237秒では再び横長の光の帯と小さな被写体に戻る。

## 実装への示唆

光源を既定の照明モデルに固定しない。背景、発光、反射、露出、蓄積、ぼけをユーザーの GPU 定義で組み合わせる。
反射像が見えることと、制作時に実際にレイトレーシングが使われたことは別であり、この映像だけから制作手法は断定しない。
文字も画像もモデルも空間の構成要素として Media に置く。カメラの初回レイ、DoF、AO、複数回反射、時間変化は別々に構成できる必要がある。

## Semantics

CPU は可変長の object/array とシーン更新、GPU は型付き値（float/vec2/vec3/vec4/Hit）とピクセル並列実行を担当する。
GPU で任意の JS オブジェクトを動的生成することはできないため、プロパティアクセスをコンパイル時に型検査する。
`get ray` はシーンを trace し、hit/position/normal/diffuse/distance を持つ値を返す。
uv はピクセル中心の正規化座標、原点は左下。色は linear RGBA とする。
